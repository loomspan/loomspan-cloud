# Cloud Publication ZIP Adapter Testing Plan

## Change Summary

Verify the adapter at the servlet and archive boundaries. It receives the original multipart ZIP, reads only execution files, and hands Framework unchanged YAML with pack-relative source names.

## Impacted Areas and Risks

| Category | Risk | Planned evidence |
| --- | --- | --- |
| Multipart transfer | ZIP bytes could be fully buffered before a size check, or multipart overhead could consume the ZIP allowance | A real embedded servlet accepts a chunked exact-limit part and rejects an oversized one before controller dispatch |
| Archive metadata | A false count or alternate central directory could bypass preflight | Explicit directory boundary plus forged central counts and an invalid directory envelope |
| Expansion | Declared lengths could understate execution expansion, or expansion accounting could exclude companions | Exact and above-limit fixtures, forged execution length, and compressed companion accounting |
| Path and type | Normalized names, prefix collisions, or nonregular execution entries could enter the execution input set | Real ZIP fixture entries and header mutations, with offending paths in the errors |
| Diagnostics | Extraction could rewrite YAML or lose the authored source path | Exact string and Framework `SkillDocument.sourceName` assertions |

## Existing Coverage and Environment Constraints

The Cloud Java module has no baseline test sources. Its Spring Boot 4.2.0-RC2 starter and Commons Compress dependencies are available in the local Maven repository. Use JUnit Jupiter with generated fixtures and only local loopback for the test-only servlet. The Maven baseline packages successfully with PowerShell, JDK 21.0.2 from `JAVA_HOME`, and Maven 3.9.11 at `C:/hamdev/maven39/bin/mvn.cmd`. There are no service credentials or external calls in this test plan.

## Tests to Add or Update

### 1. `extractsOnlyExecutionInputsWithOriginalSourceNames` and `acceptsPortablePackWithoutSkills`

- Type — Unit.
- Location — `execution-engine/src/test/java/ai/loomspan/cloud/engine/PublicationZipAdapterTest.java`
- Proves — The output contains the literal portable YAML and precisely the expected pairs of source name and skill YAML.
- Inputs — `milestone/loomspan/skills/orders/find-order.yaml`, `milestone/loomspan/skills/echo-release.yaml`, mixed-case companion paths, explicit directory entries, and a minimal `loomspan: {}` pack without skills or explicit directories.
- Boundary isolation — Generated byte arrays passed through standard test parts. No Framework reload.
- Edge cases — Include a nested authored variable key or alias in the portable text and confirm byte-preserving UTF-8 decoding. Include a syntactically valid but semantically invalid skill or owner key and assert the adapter leaves it for Framework.

### 2. `enforcesTheIncomingPackPartLimitBeforeDispatch`

- Type — Embedded servlet integration.
- Location — `execution-engine/src/test/java/ai/loomspan/cloud/engine/PublicationMultipartTest.java`
- Proves — Operating Spring/Tomcat multipart configuration enforces the inclusive decimal pack cap before controller handling, and metadata and boundary bytes do not subtract from the pack allowance.
- Inputs — Real multipart requests with 1,000,000 and 1,000,001 pack bytes, a separate small metadata part, and transfer without relying on a per-part length header. An exact-limit valid ZIP fixture can embed stored companion bytes to pad its whole on-wire length, including its central directory and metadata.
- Boundary isolation — A test-only Boot web app with normal multipart auto-configuration and the production properties. Start an ephemeral loopback port and instrument its dispatch count. Minimum test invocation uses a test-only controller that resolves the servlet `Part` before entering the method body.
- Edge cases — Include a body with unknown total length or raw chunked transfer. Assert the oversized request fails and leaves controller dispatch count unchanged. Assert multipart file-size enforcement and zero disk threshold are active from bound settings.

### 3. `enforcesZipBytesReadAndActualCentralEntryCount`

- Type — Adapter and preflight unit tests.
- Location — `execution-engine/src/test/java/ai/loomspan/cloud/engine/PublicationZipAdapterTest.java`
- Proves — The adapter independently stops a stream at its allowed bytes and preflight enforces actual entry count before indexing.
- Inputs — Stored companion padding to reach exactly 1,000,000 and 1,000,001 total archive bytes. Generate an archive of exactly 1,000 central entries, almost all explicit directories, then add one. Include a 1,001-entry archive with underclaimed EOCD entry totals and a truncated or out-of-bounds central record.
- Boundary isolation — A counting stream behind a test part underreports `getSize()` and includes spare trailing bytes. Check limit failure occurs near the boundary without consuming the longer stream. Directly exercise the preflight for the forged-count case so failure is attributable to actual entry enumeration. Include a generated single-disk ZIP64 case as a compatibility control.
- Edge cases — Test an archive comment containing a false end marker and ensure it cannot redirect preflight or the reader to different central directories.

### 4. `enforcesExpandedBytesBeforeRetainingEachChunk` and `skipsCompanionPayloads`

- Type — Adapter unit tests.
- Location — `execution-engine/src/test/java/ai/loomspan/cloud/engine/PublicationZipAdapterTest.java`
- Proves — Aggregate expansion accepts 10,000,000 bytes, rejects the next byte, and applies no per-file limit. Companion content remains compressed in the seekable adapter.
- Inputs — Compressible skill text greater than 1,000,000 bytes plus a small configuration, totaling exactly 10,000,000 and then 10,000,001 bytes. Include an otherwise valid execution fixture combined with a companion whose declaration pushes the aggregate above the ceiling. Forge a highly compressible execution entry whose actual expansion exceeds 10,000,000 while its central declaration remains below the limit.
- Boundary isolation — Assert the forged case fails at the expanded-byte boundary with the affected path. As a check that a companion payload is never opened, corrupt its compressed payload while keeping its bounded central metadata and paths valid. Adapting still returns the execution documents.
- Edge cases — Explicit directories consume entry allowance. A path containing traversal under a companion folder still fails before any content is skipped.

### 5. `rejectsInvalidPathsLayoutAndExecutionEntryTypes`

- Type — Parameterized adapter unit tests.
- Location — `execution-engine/src/test/java/ai/loomspan/cloud/engine/PublicationZipAdapterTest.java`
- Proves — The path inventory rejects invalid top-level and execution structures and reports the offending path.
- Inputs — Traversal under a companion folder, backslash, absolute path, double separator, conflicting central/local spelling, wrong or extra root, root file, wrong configuration name and case, missing configuration, file directly in the execution root, skill with a wrong extension, uppercase skills component, nonregular execution file, same-path duplication and differing case in a repeated explicit or implied execution ancestor.
- Boundary isolation — Generate ZIPs directly through the fixture writer and use targeted header byte mutations where the writer itself would normalize or disallow a negative case.
- Edge cases — Disallow file/directory prefix conflicts. Allow explicit directories alongside matching implied parents. Assert the full pack-relative path, offending uppercase component, and both authored paths where a collision is reported.

### 6. `rejectsAuthoredReservedSectionsByFieldPath`

- Type — Parameterized adapter unit tests.
- Location — `execution-engine/src/test/java/ai/loomspan/cloud/engine/PublicationZipAdapterTest.java`
- Proves — Direct or aliased authored sections are rejected regardless of contents.
- Inputs — An empty `session` mapping, null `execution-trace`, both authored reserved keys, a top-level aliased `loomspan` mapping, and a non-reserved nested data field named `session` as a control.
- Boundary isolation — Use generated miniature archives and assert `loomspan.session` and `loomspan.execution-trace` as applicable.
- Edge cases — Check quoted reserved key spelling and original retained configuration for the non-reserved control.
